# MuscleX Member App — Screen-by-Screen Audit & "Be #1" Gap Plan

**Date:** 2026-08-01 · **Audited from:** the actual code in `app/` + `src/` (48 route files, ~70 BFF endpoints in `src/api/endpoints.ts`), cross-checked against `docs/features_list.md` (stale — seeded 2026-06-03) and `MEMBER_APP_MASTER_PLAN.md`.

> **Honesty key** — every row states how it was verified:
> `code` = read the implementation this audit · `tracker` = features_list.md claimed runtime-verified · `unverified` = exists but never proven on a device.
> The app **cannot run in Expo Go** (needs a dev build), so *nothing* here has recent on-device QA. Web preview (`npm run web`) is the only runtime check available from a desk.

---

## 1. What the app is today (executive summary)

A **gym-attached member super-app** with a genuinely large surface: the core gym loop (check-in → workout → classes → membership → payments) is real and server-backed, plus nutrition, exercise library, body progress, trainer chat, an AI coach, community/gamification, health & wearable foundations, an on-device step tracker, and a public (gym-less) user mode. **~40 functional screens. No fake data anywhere — that discipline held.**

The honest state: **breadth is there, polish and proof are not.** The three things between this app and "top of market":
1. **Nothing is device-proven** — camera check-in, push delivery, HealthKit/Health Connect, haptics are all `unverified`.
2. **The differentiators are shallow** — AI coach is one chat thread; readiness "one number" absent; social layer absent.
3. **The redesign** — clay/cream tokens shipped 2026-08-01 re-theme every screen automatically, but no screen has been *redesigned* to the new language yet.

---

## 2. Information architecture (as built)

```
Splash (index) → onboarding/intro (pre-auth) → welcome → phone → otp
              → choose-gym | goal → onboarding/setup (10-step) → (app)

Bottom bar:  Home · Search · Progress · Advice · Profile   (flat, custom FitTabBar — NO centre FAB;
             check-in lives on the Home screen. Verified live 2026-08-01.)
Hidden tabs (routed, not in bar): workout, classes, community, rewards, menu
Stacks: checkin, coach, plan, nutrition, exercises/[id], body, statistic, health,
        sleep, heart, activity, mindfulness, membership, messages/chat, notifications,
        referral, tools, gyms/gym/[tenantId], locations, settings/*
```

Two user classes: **gym members** (full surface) and **PUBLIC users** (`public.app_users`, phone-keyed, gym-less — gym-only tiles hide; routes 403-guard server-side).

## 4. What's actually missing to be #1

Ranked by (member impact × competitive necessity), informed by `docs/competitive-strategy-2026-06/` (thesis: **win as the gym-attached app; the flywheel is the verified check-in** — competitors like cult.fit/Fittr/HealthifyMe can't fake that data).

### P0 — Trust & proof (weeks, not features — nothing else matters if these fail)

| # | Gap | Why it gates everything |
|---|---|---|
| 0.1 | **Device dev-build + QA pass** (EAS) | Camera check-in, push, haptics, pedometer, HealthKit/Health Connect are ALL unverified. One build unlocks proof for ~10 "built" features |
| 0.2 | **Live payment keys verified end-to-end** | Renew flow is coded but test keys 401'd; a member who can't pay is churn |
| 0.3 | **Push delivery live** (FCM creds + EAS projectId) | Every retention loop (streaks, class reminders, coach nudges) is dead without it |
| 0.4 | **Onboarding intro image downscale + clay reskin** | 78 MB of photos in the first screen; lime accents contradict the brand |

### P1 — The differentiators (the "why MuscleX over cult.fit" layer)

| # | Gap | What "top" looks like |
|---|---|---|
| 1.1 | **Readiness "one number"** | Daily 0–100 score from check-ins + workouts + steps + sleep/HR when available. WHOOP/Oura's hook, grounded in *verified gym data* nobody else has. Feeds Home hero |
| 1.2 | **AI Coach v2** | Today: bare chat. Top: grounded in the member's real workouts/nutrition/readiness, proactive daily brief, explains *why*, can modify the plan. This is the #1 tracked competitive gap |
| 1.3 | **Progressive overload + PR engine** | Auto-suggest next weights, PR detection + celebration moments. Retention gold, data already logged |
| 1.4 | **Exercise video demos** | Library is images-only; every top competitor has video/animation |
| 1.5 | **Barcode scanner + diet-plan templates** | HealthifyMe's moat; catalog + AI coach make this cheap to add |
| 1.6 | **Chat v2: WebSocket + voice/images** | Polling text-only reads 2019; trainers are a paid-tier lever |

### P2 — The retention & growth layer

| # | Gap | Notes |
|---|---|---|
| 2.1 | Social feed (posts/reactions) — **gated on moderation tooling** | Community currently = leaderboard only; feed is the daily-open driver |
| 2.2 | Transformation sharing + shareable workout/PR cards | Free acquisition; progress photos already exist |
| 2.3 | Streak insurance / smart reminders / batched nudges | Duolingo-grade streak mechanics; needs 0.3 |
| 2.4 | Recurring class booking + calendar sync | Waitlist done; these two complete the loop |
| 2.5 | Wearable cloud OAuth (Fitbit/Garmin) + Samsung Health G2–G5 | After bridges are device-proven |
| 2.6 | Premium member tier | Monetizes 1.1/1.2/1.6; needs payments proven |
| 2.7 | Accessibility pass (AA, dynamic type, reduced motion) | Zero work done; also a store-review risk |

## 5. Suggested sequence

1. **P0 in one slice each** (device build → payments → push → intro fix) — 4 slices.
2. **Redesign sweep (P3) interleaved with P1**, money path first — the redesign touches every screen anyway, so P1 features land *in* the new language instead of being reskinned later.
3. P1 order: 1.3 (cheap, data exists) → 1.1 (needs step/health data flowing post-device-build) → 1.2 (builds on 1.1) → 1.4/1.5 → 1.6.
4. P2 after the first P1 wins ship.

*`docs/features_list.md` was NOT updated by this audit — its protocol requires shipped+tested changes only. It is ~2 months stale (waitlist, coach, plans, rewards/menu/search tabs all missing from it); reconciling it against §3 above is a worthwhile follow-up slice.*
