## 🔴 NEEDS YOUR APPROVAL — schema drift breaks the Members page

**`GET /api/v1/members` returns 500.** The members list — the most-used page in
the app — is broken, and so is `/mama/crm` which loads the same endpoint.

**Cause:** `schema.prisma` declares three things the database has never had:

| Object | Type |
|---|---|
| `members.schedule_offset_days` | `Int NOT NULL DEFAULT 0` |
| `workout_logs.routine_id` | `uuid NULL` |
| `member_routine_schedule` | whole table |

They were added to the schema with **no migration generated**, so Prisma selects
a column Postgres doesn't have → `P2022` → 500.

**This is NOT caused by the Mumbai migration** — I verified the columns were
missing on the old Singapore database too. It is pre-existing drift.

**Migration is written but NOT applied** (CLAUDE.md HARD STOP #1):
`backend/prisma/migrations/20260902_member_routine_schedule/migration.sql`

It is idempotent and propagates across `studio_template` + every live `studio_*`
schema, following the convention in `scripts/run-pending-migrations.ts`.

To apply after review:
```bash
# inspect first
cat backend/prisma/migrations/20260902_member_routine_schedule/migration.sql
# then, against the Mumbai DB
psql "$DATABASE_URL" -f backend/prisma/migrations/20260902_member_routine_schedule/migration.sql
```

## ✅ FIXED AND VERIFIED

### 1. SCC Analytics page 500 — `relation "tenants" does not exist`
`analytics.service.ts` had `LEFT JOIN tenants` in a raw query. Prisma's
`$queryRaw` does not resolve the schema mapping, and the table is `scc.tenants`.
**Fix:** qualified the table. **Verified:** `analytics/growth` 500 → **200**.
Swept every other raw query in the SCC — this was the only unqualified one.

### 2. Reports page — campaign analytics 400
The Reports page sends `branch_id` on every analytics call, but
`CampaignAnalyticsQueryDto` omitted it, so the global `forbidNonWhitelisted`
pipe rejected the whole request. **Fix:** accept `branch_id`, documented as
deliberately unfiltered (campaign_analytics has no branch column; the query is
already tenant-scoped). **Verified:** 400 → **200**.

### 3. Invoice settings — invalid HTML / hydration warning
Template cards were `<button>` elements containing the Preview `<button>`.
Nested buttons are invalid HTML and React logged a hydration warning.
**Fix:** outer element is now a `div` with `role="button"`, `tabIndex`,
`aria-pressed` and Enter/Space handling, so keyboard use is preserved.

### 4. Test regression from my own coupon work
`test/subscription/subscription-gateway.service.spec.ts` constructs
`SubscriptionService` directly and broke when I added the coupon dependency.
Fixed; **973 tests pass**.

## ✓ INVESTIGATED — not bugs

- **`/admin/referrals*` 403s** — correct. Platform-admin routes properly
  refusing a gym owner. Authorization working as designed.
- **24/28 SCC routes "failing"** — my crawler couldn't persist the SCC session
  (token in localStorage, not cookies). Tested every endpoint directly with a
  real token instead: all 200 except the analytics bug above.
- **Slow route times (7–20s)** — Next.js **dev-mode** per-route compilation, not
  runtime performance. Warm API calls are 0.9–2.2s *from a laptop* (66ms RTT to
  Mumbai); from the VPS (~5ms RTT) they are far faster.
- **`pg_stat_statements` top queries** — all Supabase Studio/PostgREST
  introspection, not app queries. **No significant N+1 problem.**

## ⚠️ DEAD CODE — deliberately NOT removed

45 unreferenced exports across 19 files. **I removed none of them**, because
verification showed the naive answer was wrong:

- `scrubSentryEvent` / `scrubSentryBreadcrumb` looked dead but are imported by
  `sentry.client.config.ts` at the project root. **Deleting them would have
  leaked PII to Sentry.** My first scan missed it by only indexing `src/`.
- `gym-referrals/hooks.ts` (16 exports) and `expenses/offline-queue.ts` are
  **live features** — their pages import other symbols from the same modules.

What remains is unused *exports inside live modules* — normal partial API
surface, cosmetic at best. The full list is in the audit artifacts if you want
to prune it deliberately.

**Also rejected:** the "unused dependency" scan flagged `reflect-metadata`,
`react-dom`, `passport`, `pino-http` — all framework runtime requirements loaded
implicitly. Removing them would break the apps.
